# 0010 — `cos net`: is it the Wi-Fi, the router, or the internet?

- **Status:** accepted
- **Date:** 2026-10-25
- **Decided by:** the board, from the roadmap's Ideas (0005 asked for its own proposal)

## Context

"Why is my internet slow?" is one of the most common Mac questions, and Claude OS could only
answer it with improvised shell. 0005 held `cos net` back because the Wi-Fi network's name is
personal and reading it needs Location.

## Votes

|---|---|---|
| Architect | amend | The probes are mechanics and the verdict is deterministic, so a syscall. Read Wi-Fi through CoreWLAN (50 ms) rather than `system_profiler` (~10 s, and it lists nearby networks). `--speed` needs the same enforcement as `startup --full`. |
| Guardian | amend | The raw sources carry the network's name, hardware addresses, nearby networks, search domains and VPN names that often name an employer. | Steward | amend | Rare but a big relief when it happens, and free to keep around. Lead with one plain line, keep it fast, run only when asked. |
| Skeptic | amend | "Unknown" must be a real answer (routers drop pings, caches answer DNS, utun interfaces exist with every VPN off). CLI only for now: no desktop card, no state file, no journal line for a check. |

**Approved, with conditions.**

## Decision

- **`cos net`** (read-only, a few seconds, all probes at once inside a 5 s budget):
  - Wi-Fi from one fixed JXA script over CoreWLAN, reading eight properties of the current
    connection: power, signal, noise, link rate, channel, band, width and PHY mode. A test
    checks that the script never mentions the network's name, a hardware address, the
    country code, scanning, profiles or configuration.
  - The default route's interface (Wi-Fi, Ethernet, VPN, iPhone).
  - The router: whether the ARP table has a complete entry for it, yes or no (see below).
  - A VPN counts only if `scutil --nc` says a service is Connected or the default route
    goes over a tunnel. Names are never read.
  - DNS: the time to look up a name nobody has asked for before, so no cache answers.
  - The internet: Apple's captive-portal page, connect time, and whether something answered
    in its place. Redirects are never followed.
  - One verdict line first, the single likeliest cause or "Network looks fine", with "Can't
    tell" allowed; the numbers below it.
- **`cos net --speed`** runs macOS's `networkQuality` (about 20 s, real data). It's written
  canonically, has ask rules, is refused in daemons and keeps only throughput and
  responsiveness. It's the one part that's journaled.
- **Never kept, printed or journaled:** the network's name, the router's or any hardware
  address, nearby networks, the country code, DNS search domains, addresses, VPN names.
- **Not in this change:** a desktop card, a pulse signal, a boot banner line, a state file.
  Revisit the card once friction shows the human asks for it.
- **Amended 26 October (weekly board):** the human asked "is my internet slow?" twice in
  three days, so Vitals has a Network card. It runs the same check only when clicked, never
  on Vitals' 15-second refresh (`GET /api/net`, `net.summary`): the verdict, then at most
  three numbers, nothing that names the network or the Mac, nothing kept. It also answers
  when the internet is down, which the chat can't. "Test speed…" goes through the chat, so
  `cos net --speed` keeps its Allow card. Still no pulse signal, banner line or state file.

## What the first real run changed

The design pinged the router to tell "the Wi-Fi" from "the internet". On the first run, from
a terminal app other than Terminal.app, the ping failed with `sendto: No route to host`
while the router sat in the ARP table: macOS's Local Network privacy covers ICMP too, and
only exempts Terminal, SSH, root and launchd daemons. From Claude OS.app's chat, the first
ping could put a Local Network alert in front of the human. So `cos net` sends nothing to the
local network: the router check reads the ARP table, which sends no packets, and the "slow
link to the router" verdict went with the ping. Wi-Fi signal and noise cover most of it.
