# 0002 — v0.3 priorities (first board meeting)

- **Status:** accepted
- **Date:** 2026-10-24
- **Decided by:** the board, chaired by Claude

## Question

The human said "continue on your roadmap as you please" after v0.2 (the desktop app).
Which of seven candidates should v0.3 take on?

## Votes (ranked)

| Seat | Vote | Top reason |
|---|---|---|
| Architect | F, A, C | F is the only open friction; A and C fit cleanly in one layer each |
| Guardian | A, G, C · **veto F** (Accessibility route) | Granting Accessibility to Claude OS.app would extend to every Claude session it spawns: keystrokes anywhere, no Allow/Deny card |
| Steward | F, D, B | Music was the human's first request; D answers "do I need to clean up?" with real gigabytes |
| Skeptic | B, D, C | A blind Return keypress can land in the wrong app; demo mode is permanent code for one-off screenshots |

Candidates: A demo mode, B calendar, C trends, D old simulator runtimes, E weather,
F reliable catalog playback, G startup audit.

## Decision

1. **F, without new permissions.** All four seats said: try the Shortcuts route first.
   Music exposes `PlayMusicItemSiriIntent` to Shortcuts; `cos music play` now uses a
   human-made "Claude OS Play" shortcut when it exists, verifies what's playing, and falls
   back otherwise. The Accessibility/keypress route stays vetoed.
2. **D**: `simulator-runtimes-old` cleanup target, safety *review*, never the newest
   runtime per platform.
3. **C, logging only**: pulse appends one snapshot a day to `trends.jsonl`; sparklines wait
   for 14+ days of data (Skeptic's condition).
4. **A, the Architect's way**: one fixtures module (`lib/cos/demo.py`), no `if demo` checks
   scattered through the syscalls, scripted chat stub, writes are no-ops. README
   screenshots come from it, so no real machine is ever shown.

Deferred: **B** (behind a user-initiated Connect button, v0.4), **G**. Rejected for now:
**E** while the only location would be a guess; weather waits for a location the human sets.
